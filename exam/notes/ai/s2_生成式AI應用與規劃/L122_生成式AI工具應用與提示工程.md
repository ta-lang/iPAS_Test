### 1. 生成式 AI 多模態工具矩陣

隨著技術演進，生成式 AI 工具已覆蓋多種資訊模態，以下為官方評鑑大綱重點涵蓋的主流工具：

| 應用領域 | 代表性工具 / 平台 | 核心技術特性 | 典型企業級應用場景 |
|---|---|---|---|

### 2. LLM 推論核心超參數 (Hyperparameters) 調控

在呼叫 OpenAI API 或開源 LLM（如 LLaMA）時，參數設定直接影響模型的創造力與嚴謹度：

| 參數名稱 | 數值範圍 | 參數物理意義 | 調高參數時的行為 | 調低參數時的行為 | 典型設定建議 |
|---|---|---|---|---|---|
| **Temperature**<br>*(溫度)* | 0.0 ~ 2.0 | 控制輸出機率分佈的平坦程度（平滑度） | 機率分佈平緩，**隨機性與創造力高**，易產生意外火花（也易幻覺） | 機率分佈陡峭，**確定性高、保守嚴謹、重複性高** | • 程式碼/合約/數學：**0.0 ~ 0.2**<br>• 創意文案/故事：**0.7 ~ 1.0** |
| **Top-p**<br>*(核採樣 Nucleus)* | 0.0 ~ 1.0 | 僅在累積機率達到閾值 $p$ 的 Token 候選集合中動態採樣 | 擴大候選詞彙池，內容多樣富變化 | 縮小候選池，僅在最高機率的前幾個核心單詞中挑選 | 一般與 Temperature 二擇一調整，避免同時變動 |
| **Top-k** | 正整數<br>*(如 10~50)* | 嚴格截斷僅挑選機率最高的前 $k$ 個 Token 進行再採樣 | 詞彙選擇更廣泛豐富 | 嚴格鎖定少數詞，避免罕見低機率詞出現 | 常用於開源本地模型防範語義胡言亂語 |

## 📌 L12202 如何善用生成式 AI 工具

### 1. 提示詞工程 (Prompt Engineering) 核心框架

提示工程是利用自然語言有效引導大型語言模型輸出高品質答案的技術。

#### A. 優秀 Prompt 必備四大結構要素 (CRFC 框架)
1. **角色設定 (Role / Persona)**：賦予 AI 具體身份背景（如：「你是一位擁有 15 年資歷的製造業資安審計顧問」）。
2. **上下文背景 (Context)**：提供充分的情境資訊（如：「我司為汽車零件製造廠，正準備通過 ISO 27001 認證」）。
3. **任務指令 (Instruction / Task)**：清晰明確的動作指示，避免模糊詞句（如：「請列出產線 OT 網路實體隔離的五大檢查重點」）。
4. **輸出格式與約束 (Format & Constraints)**：指定排版結構與禁止事項（如：「以 Markdown 三列表格呈現，嚴禁使用未經驗證的縮寫，字數控制在 300 字內」）。

#### B. 主流提示詞設計技巧對比

| 技巧名稱 | 運作機制 | 適用任務 |
|---|---|---|
| **Zero-shot Prompting**<br>*(零樣本提示)* | 直接向模型下達指令，不提供任何參考範例 | 常識問答、標準翻譯、簡易文字潤飾 |
| **Few-shot Prompting**<br>*(少樣本提示)* | 在提問前先給予 2~3 組高質量的「輸入-輸出」示範樣本 | 特殊輸出格式對齊、特定風格語氣模仿、情感極性分析 |
| **Chain-of-Thought (CoT)**<br>*(思維鏈提示)* | 引導模型輸出「**讓我們一步一步思考 (Let's think step by step)**」之推理軌跡 | 複雜數學應用題、邏輯推理、跨系統排錯診斷 |

### 2. 檢索增強生成 (RAG, Retrieval-Augmented Generation) 核心架構

#### A. RAG 架構全景流程圖

```
【離線文檔索引階段 (Offline Indexing)】
  企業內部私有文檔 (PDF / Word)
        │
        ▼ (切塊 Chunking)
  文檔片段 (Chunks, 500 tokens)
        │
        ▼ (調用嵌入模型 Embedding Model)
  高維向量矩陣 (Vectors, e.g., 1536-dim)
        │
        ▼ (持久化儲存)
  【向量資料庫 Vector Database】 (如 Milvus, Pinecone, Chroma)

─────────────────────────────────────────────────────────────

【在線即時問答階段 (Online Inference)】
  使用者查詢 (User Query) ──► (嵌入向量化 Embedding) ──┐
                                                      ▼
  【向量資料庫】 ◄────── 語義相似度搜尋 (Cosine Similarity) ┘
        │
        ▼ (檢索出 Top-k 最相關的企業內部 Context 片段)
  【豐富提示詞構建】 = [系統指令] + [內部真實 Context 片段] + [用戶問題]
        │
        ▼ (送入大語言模型推理)
  【大型語言模型 (LLM)】
        │
        ▼
  精準回答 (具備內部知識、完全不產生虛假幻覺、附帶原始文檔出處引用)
```

#### B. RAG 核心優勢與關鍵價值 (Exam Traps)
1. **徹底緩解模型幻覺 (Mitigate Hallucination)**：模型強制依據檢索到的真實文件 Context 作答，無據不答。
2. **免除高昂重新訓練成本**：**無需重新預訓練 (Pre-training) 或微調 (Fine-tuning)**，當公司規章更新時，僅需更新向量資料庫內的單一文檔即可即時生效。
3. **動態權限與敏感資料隔離**：可結合企業 AD/LDAP 權限，不同員工僅能檢索到具備存取授權的向量空間。
4. **即時性與時效性**：突破大模型訓練數據截斷（Knowledge Cutoff）之先天限制。

### 3. 實戰情境計算題：餘弦相似度 (Cosine Similarity) 檢索原理

> **【實戰範例】**：
> 在 RAG 檢索時，使用者提問向量化後為向量 $\mathbf{A} = [1, 2]$。
> 資料庫中有兩篇內部知識文章片段，其嵌入向量分別為：
> * 文件 1：$\mathbf{B}_1 = [2, 4]$
> * 文件 2：$\mathbf{B}_2 = [2, -1]$
> 
> 請計算兩篇文章與使用者提問之餘弦相似度，並判斷 RAG 系統應優先檢索哪一篇？
> 
> **【計算解析】**：
> 1. 餘弦相似度公式：
>    $$\text{Cosine Similarity} = \frac{\mathbf{A} \cdot \mathbf{B}}{\|\mathbf{A}\| \|\mathbf{B}\|}$$
> 2. 計算 $\mathbf{A}$ 與 $\mathbf{B}_1$：
>    * 內積：$\mathbf{A} \cdot \mathbf{B}_1 = (1 \times 2) + (2 \times 4) = 2 + 8 = 10$
>    * 模長：$\|\mathbf{A}\| = \sqrt{1^2 + 2^2} = \sqrt{5}$，$\|\mathbf{B}_1\| = \sqrt{2^2 + 4^2} = \sqrt{20} = 2\sqrt{5}$
>    * 相似度：$\text{Cos}(\mathbf{A}, \mathbf{B}_1) = \frac{10}{\sqrt{5} \times 2\sqrt{5}} = \frac{10}{10} = 1.0$（方向完全一致，平行）
> 3. 計算 $\mathbf{A}$ 與 $\mathbf{B}_2$：
>    * 內積：$\mathbf{A} \cdot \mathbf{B}_2 = (1 \times 2) + (2 \times -1) = 2 - 2 = 0$
>    * 相似度：$\text{Cos}(\mathbf{A}, \mathbf{B}_2) = 0.0$（兩向量正交，毫無關聯）
> 4. **結論**：文件 1 之相似度為 $1.0$，系統將優先把文件 1 作為上下文傳入 Prompt。

### 🎯 考前衝刺「一句話考點」
1. **Temperature (溫度)** 越接近 0，LLM 輸出越確定、保守；溫度越高，隨機性與創造力越強。
2. 進行合約審核、程式碼生成或數學計算時，Temperature 應設定為**極低值 (如 0.0 ~ 0.2)**。
3. **Top-p (核採樣)** 透過控制候選詞彙累積機率閾值來平衡生成的多樣性。
4. 提示工程結構應包含：**角色 (Role)、背景 (Context)、指令 (Task) 與格式限制 (Constraints)**。
5. **思維鏈 (CoT, Chain-of-Thought)** 透過引導模型逐步推導，顯著提升複雜邏輯推理準確率。
6. **RAG (檢索增強生成)** 透過「外掛向量資料庫」即時檢索私有知識，能**大幅降低模型幻覺**。
7. RAG **不需要重新微調 (Fine-tune) 或重新訓練模型**即可實現內部私有文檔問答。
8. 向量資料庫（如 Milvus, Pinecone）透過**高維嵌入向量的餘弦相似度**進行語義比對檢索。
9. **GitHub Copilot** 與 **Cursor** 為深度整合現代程式碼編輯器的 AI 輔助開發工具。
10. 當企業規章文件頻繁變動時，更新 **RAG 向量資料庫**是成本最低、反應最即時的架構方案。
