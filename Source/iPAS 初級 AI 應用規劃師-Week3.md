# 📚 第三週完整課程資料：Low Code / No Code 概念與生成式 AI 工具應用

本週課程完全依據初級 AI 應用規劃師的官方評鑑範圍，聚焦於 **L121 No code / Low code 概念** 與 **L122 生成式 AI 應用領域與工具使用** 。本篇教材將深入探討低程式碼與無程式碼工具的理論、主流生成式 AI 工具的應用場景，以及在商業環境中導入這些工具的核心關鍵。

## 📑 單元一：L121 No code / Low code 概念

### 1. 基本概念與基礎認知（L12101）

- **定義** ：
    
    - **No-Code（無程式碼）**：開發者完全不需要撰寫任何一行傳統程式碼 。系統透過視覺化的直覺界面、拖拉組件（Drag-and-Drop）與設定邏輯規則的方式，快速建構出應用程式或自動化工作流 。
        
    - **Low-Code（低程式碼）**：開發過程仍以視覺化界面為主，但在需要處理高度客製化邏輯、系統對接或複雜資料轉換時，允許並需要開發者撰寫少量的傳統程式碼來延伸其功能。
        
- **演進背景與目的** ： 為了因應數位轉型過程中，企業內工程師人力普遍短缺、資訊需求變動快速的痛點。低程式碼 / 無程式碼工具旨在降低非技術背景人員（又稱公民開發者，Citizen Developer）的進入門檻，將創意與業務邏輯直接轉化為數位解決方案 。
    

### 2. 優勢與限制（L12102）

理解這些工具在各個產業場景實際落地時的利弊得失，是規劃師的核心評鑑考點 。

#### 📈 核心優勢：

- **加速開發與敏捷迭代（Time-to-Market）**：能以極快的速度打造出最小可行性產品（MVP），即時根據市場或內部反饋進行修改，縮短專案週期 。
    
- **降低開發與維護成本**：減少對高階軟體工程師的依賴，使非 IT 部門的業務人員（LOB）也能親自優化自身的工作流。
    
- **消弭產權溝通落差**：業務人員本身最懂需求痛點，親自拖拉設計能大幅減少過往與工程師溝通規格時的雞同鴨講。
    

#### 📉 核心限制與潛在風險：

- **客製化彈性低（Flexibility Limitation）**：一旦業務邏輯超出工具預設的組件範圍，將很難或完全無法透過調整界面來實現。
    
- **平台鎖定風險（Vendor Lock-in）**：應用程式高度綁定於該特定平台上，若未來平台調漲授權費或終止服務，企業很難將系統無縫遷移至其他平台。
    
- **影子 IT（Shadow IT）與資安隱患**：當非技術人員能夠隨意建立自動化流程時，若缺乏 IT 部門的集中化管控與權限治理，容易發生企業內部機密資料外洩、不符法規的資安漏洞。
    

## 📑 單元二：L122 生成式 AI 應用領域與工具使用

在生成式 AI 的商業落地規劃中，必須熟悉多種常見工具的適用場景、操作邊界與核心延伸技術 。

### 1. 生成式 AI 應用領域與常見工具（L12201）

根據考綱規範，生成式 AI 工具主要依據三大媒介領域進行分類 ：

#### ✍️ A. 文本與通用對話領域（Text Generation）

- **常見工具** ：**OpenAI API、ChatGPT、Gemini**。
    
- **應用場景** ：
    
    - 企業智慧客服、法規法律文件摘要、多國語言合規繙譯。
        
    - 行銷文案自動生成、市場輿情分析報告撰寫。
        

#### 🎨 B. 圖像與多媒體生成領域（Image Generation）

- **常見工具** ：**Midjourney**。
    
- **應用場景** ：
    
    - 電商產品背景圖合成、社群媒體視覺素材快速產出、工業設計概念圖盲測。
        

#### 💻 C. 開發輔助與程式碼生成領域（Code Generation）

- **常見工具** ：**GitHub Copilot、VS Code for Copilot、Cursor**。
    
- **應用場景** ：
    
    - 程式碼自動續寫與補全、Legacy Code（舊系統程式碼）重構與解讀、自動化測試腳本（Test Cases）編寫，大幅提升開發團隊的生產力。
        

#### 🤖 D. 企業自動化與 Agent 領域

- **常見工具** ：**Copilot Studio**。
    
- **應用場景** ：
    
    - 允許企業利用 Low-code 界面，串接內部知識庫與 ERP 系統，快速配置出具備特定工作流引導能力的「企業專屬 AI 助理（Agent）」 。
        

### 2. 如何善用生成式 AI 工具（L12202）

僅了解工具有哪些是不夠的，規劃師必須掌握如何精準驅動這些工具的關鍵技術方法 。

#### 💡 提示工程（Prompt Engineering）的核心原則

提示詞不只是對 AI 說話，而是一種結構化的輸入。高質量的 Prompt 通常包含以下核心元素：

1. **角色設定（Role）**：明確定義 AI 的專家身份（例如：「你是一位擁有 10 年經驗的資深個資法法務顧問」）。
    
2. **上下文背景（Context）**：提供清楚的背景資訊、限制條件與企業當前面臨的現狀。
    
3. **任務目標（Task）**：具體且動詞明確的指令（例如：「請摘要、請列出、請重構」）。
    
4. **輸出格式限制（Output Format）**：限定 AI 回覆的格式（例如：以 Markdown 表格呈現、字數限制在 300 字以內、嚴禁使用專業術語）。
    

#### 💡 RAG（檢索增強生成，Retrieval-Augmented Generation）

- **為了解決什麼問題？** 大型語言模型（LLM）天生具備「幻覺（Hallucination）」的技術缺陷，即在面對不知道的事情時會一本正經地胡說八道；此外，模型的知識庫受限於預訓練截止時間，無法取得最新或企業內部的私有機密資料。
    
- **RAG 的運作機制**：
    
    RAG 不去更改大模型本身的參數，而是在模型回答之前，外掛一個企業專屬的知識庫（通常是向量資料庫 Vector Database）。
    
    1. 當使用者輸入問題時，系統先去企業知識庫中「檢索（Retrieve）」出最相關、最正確的最新文件片段。
        
    2. 系統將這些真實的文件片段與使用者的原始問題打包在一起，作為精準的上下文背景餵給 LLM。
        
    3. LLM 根據這些被限定的真實資料進行「增強生成（Generate）」，從而徹底根除幻覺，確保回覆的百分之百準確性與時效性。
        

## 📝 第三週 自我檢測模擬題

### 💡 觀念選擇題

**Q1. 某跨國零售企業的 HR 部門，希望能針對內部非工程師背景的招募同仁，推動一項數位轉型計畫：讓同仁能透過視覺化拖拉組件、設定關聯邏輯的方式，快速搭建出一個內部的「新進員工報到追蹤小工具」。請問此需求最適合採用下列哪一種概念的工具來進行開發？**

(A) 微調大型語言模型 (Fine-tuning)

(B) 傳統編譯式高階程式語言 (C++ / Java)

(C) 無程式碼 / 低程式碼平台 (No Code / Low Code)

(D) 強人工智慧系統 (AGI)

**Q2. 企業在引進 Low Code 或 No Code 工具來加速內部應用開發時，雖然能帶來顯著的敏捷度，但如果缺乏 IT 部門的集中審查與集中化治理，最容易引發下列哪一個專有名詞所代表的潛在資安與合規管理風險？**

(A) 模型漂移 (Model Drift)

(B) 影子 IT (Shadow IT)

(C) 資料歸一化 (Normalization)

(D) 人類監督 (Human-in-the-loop)

**Q3. 某金控公司希望利用生成式 AI 來打造一個內部同仁專用的「放款法規答詢機器人」。由於金融法規經常修正，且大模型容易產生「幻覺（Hallucination）」而胡亂回答，導致合規風險增加。請問以下哪一種技術架構最能協助該公司在不重新訓練大模型的前提下，有效解決幻覺問題並維持資訊的即時修正？**

(A) 提示詞中的多模態學習 (Multimodal Learning)

(B) 檢索增強生成 (Retrieval-Augmented Generation, RAG)

(C) 非監督式分群演算法 (Clustering)

(D) 轉換成低程式碼 (Low Code) 開發環境

### 🔑 答案與解析

- **Q1 答案：(C)**
    
    - **解析**：HR 同仁並非工程師背景，且需求是快速搭建內部小工具。No Code / Low Code 平台的核心定義即是透過視覺化界面與拖拉組件來建構應用，完美符合此場景 。
        
- **Q2 答案：(B)**
    
    - **解析**：業務部門未經 IT 部門允許或知情，私自採購或開發未受監管的數位工具與自動化流程，這在資安與資訊治理上被稱為「影子 IT（Shadow IT）」，是導入低程式碼工具時的主要風險之一。
        
- **Q3 答案：(B)**
    
    - **解析**：RAG（檢索增強生成）技術專門為解決大模型幻覺而生。它透過外掛動態知識庫，在回答前先撈取最新的合規法規文件提供給模型作為參考依據，完全符合既不改動大模型參數又能精準答詢的需求。
